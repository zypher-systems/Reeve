**Critical fix.** On any machine where Reeve has been used for a while, every tool call can start failing
with `io: stream did not contain valid UTF-8`, whatever the model. Update as soon as you can.

## Update

```sh
reeve update
```

If your Reeve already shows the error, `reeve update` installs 0.7.1 and then reports the same error,
because it writes its receipt after the install, with the old code. The update did happen: `reeve
--version` says 0.7.1. Restart the observer yourself, since the failed command skipped that step:

```sh
systemctl --user restart reeved
```

On 0.4.0 or earlier, run the installer once more instead:

```sh
curl -fsSL https://raw.githubusercontent.com/zypher-systems/reeve/main/install.sh | sh
```

## Fixed

- **Tool calls failing with "stream did not contain valid UTF-8".** Before each action Reeve writes a
  receipt that links to the one before it, and it finds that one by reading the last 64 KiB of the month's
  receipt log. Once the log had grown past that, a read could start in the middle of a character, such
  as an em dash in an earlier command, and the receipt couldn't be written. Reeve doesn't act without a
  receipt, so the call stopped, and since nothing new was written the log stayed the same and every call
  after it failed too, in conversations, standing orders and the observer's drafts alike. Reeve now reads
  that tail as bytes and decodes only the last line, which always starts on a character.

Your receipts were never damaged: the log reads and verifies as before, and the next action continues the
chain where it stopped.

Nothing else changed.
