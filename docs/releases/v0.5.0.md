Reeve tells you when a new version is out, and installs it with one command.

## Update

```sh
curl -fsSL https://raw.githubusercontent.com/zypher-systems/reeve/main/install.sh | sh
```

This is the last time you need that line for an update: from 0.5.0 on, `reeve update` does it.

## New

- **A tag for new versions.** reeved asks GitHub for the latest release a minute after it starts and
  every 12 hours. When a newer one is out, the header shows `↑ <version>` next to reeved's status.
  `/update` says what's out, links the release notes, and gives the command, and ⌃K lists it at the
  top. There's no popup.
  - If reeved isn't running, Reeve asks when you open it, at most once a day.
  - `[updates] check = false` in `config.toml` turns the checks off.
  - After an update, a window that's still on the old version says `restart for <version>`.
- **`reeve update`.** It installs the newest release the way Reeve was installed:
  - **With install.sh:** it downloads the release, checks it against the release's `SHA256SUMS`, and
    runs that release's own installer over your copy, using sudo only for a system install.
  - **From the release RPM:** it checks the RPM the same way, shows the `sudo dnf upgrade` it will run,
    and runs it when you say yes.
  - **From pacman:** it hands over to your AUR helper.
  - **Built from source:** it says how to rebuild instead.

  It restarts reeved when reeved runs the copy it just replaced, and it leaves a receipt every time,
  failures included. `--check` only says what's out, `--version v0.5.0` installs a particular release,
  and `--rollback` goes back to the version the last update replaced, from its own release, checked the
  same way.
- **What 1.0 means.** The design now lists what has to be true before Reeve is 1.0, and what's done
  so far (`design.md`, §14).

## Changed

- **install.sh over an existing install** says `updated (0.4.0 → 0.5.0)` and skips the first-install
  notes.
- **`reeve doctor`** says whether a newer release is out.

## Heads up

- The check is one request to GitHub every 12 hours, with `reeve/<version>` as the user agent.
  Nothing else is sent.
- `SHA256SUMS` comes from the same release as the files. It catches a corrupted download or a bad
  mirror, not a compromised release.
- A copy of Reeve somewhere no installer puts it (not in a `bin/` folder) isn't replaced; `reeve
  update` says so and stops.
