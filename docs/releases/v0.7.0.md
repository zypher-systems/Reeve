Debian and Ubuntu, and a fresh session without closing Reeve.

## Update

```sh
reeve update
```

On 0.4.0 or earlier, run the installer once more instead:

```sh
curl -fsSL https://raw.githubusercontent.com/zypher-systems/reeve/main/install.sh | sh
```

On Debian and Ubuntu, that same installer is the way in: the binaries are static, so they run on any
release. There's no `.deb` yet.

## New

- **Debian and its family** (Ubuntu, Mint, Raspberry Pi OS): the package tools speak `apt-get`, and the
  same promise holds as on Fedora and Arch: every package change made through them can be taken back.
  - **Undo.** The receipt records what dpkg logged while the command ran (installed, upgraded, removed,
    with versions). Undo is one `apt-get` that puts the old versions back from `/var/cache/apt/archives`
    and removes what was new. It's simulated first (`apt-get -s`): if apt can't resolve it, or the undo
    would also remove or change a package the receipt never touched, it's refused and nothing changes. A
    version the cache no longer has is asked for by name; if the repos don't carry it either, apt says so.
  - **Installs and upgrades** run `apt-get update` first and keep a config file you edited rather than
    stopping at a prompt. An empty upgrade is `apt-get upgrade --with-new-pkgs`: nothing is removed, and
    what would need a removal is held back and listed. `pkg_remove` is `apt-get remove`: config files
    stay, and nothing else goes along.
  - **The floor** knows Debian: `libc6`, `dpkg`, `apt`, `systemd-sysv`, the bootloader packages, the
    running kernel's `linux-image`, kernel packages named by a pattern, `install foo-` as a removal,
    `--allow-remove-essential` (as a flag or an `-o` config item), and dpkg's `--force-depends` /
    `--force-all` when removing (as a flag, a comma list, a `Dpkg::Options` value, or `DPKG_FORCE`) all
    take a typed yes, in every mode.
  - **reeved** says a reboot is pending when a newer kernel package is installed, when the running
    kernel was rebuilt under the same name, or when `/var/run/reboot-required` is set, and reports
    security updates from apt. The state of the machine (`/report`) reads dpkg's log for what changed.
  - needrestart lists the services an upgrade left on old libraries instead of restarting them on its
    own. Ask Reeve to restart them: each is its own approved, undoable action.
- **`ctrl+n`: a fresh session.** The chat clears and Reeve forgets the conversation; receipts, memory,
  findings, and the board stay. `/new` does the same, now also before a model is connected. For leaving
  Reeve open as a dashboard between tasks.

## Changed

- `sys_info` reports AppArmor beside SELinux, and whether `/var/run/reboot-required` is set.
- The shell's environment sets `APT_LISTCHANGES_FRONTEND=none` and `NEEDRESTART_MODE=l`, so apt never
  waits on a pager or restarts services behind your back.
- The policy classifies `apt-get`, `apt`, `aptitude`, `dpkg`, `apt-mark`, `dpkg-reconfigure`,
  `update-alternatives`, `needrestart`, `unattended-upgrade`, and `add-apt-repository`; `apt-cache`,
  `apt-config`, `dpkg-query`, and `debsums` are reads, and `apt-get -s` makes anything a read.

## Heads up

- Undo on Debian needs the old packages in apt's cache. `apt-get` keeps them; `apt` (the friendly
  command) deletes them after each install, and `apt-get clean` empties the cache. When one is missing,
  Reeve asks the repos for that version, which works until the next point release.
- After an undo, a dependency that was marked automatic comes back marked manual, so `autoremove` won't
  offer it later. `pkg_list user` shows it.
- `pkg_list updates` is only as fresh as the last `apt-get update`. `pkg_upgrade` and `pkg_install`
  refresh the lists first.
- Tested live in Debian 12 (apt 2.6) and Debian 13 (apt 3.0) containers: install, remove, upgrade, undo
  both ways, the refusal, the cache miss, and a failed install. Not yet run on a real server, on Ubuntu,
  or on a multi-arch system.
