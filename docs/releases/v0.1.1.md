A fix for noisy notifications, and standing orders.

## Update

```sh
curl -fsSL https://raw.githubusercontent.com/zypher-systems/reeve/main/install.sh | sh
```

(or the RPM / `PKGBUILD` below). `reeved` restarts on the new binary.

## Fixed

- **One finding per crashing program.** A program that crashes over and over used to raise a new
  critical finding, and a popup, for every crash, because systemd logs each crash under a new unit.
  Crashes are now one `app-crash:<program>` finding (a warning) with a count. abrt's report of the
  same crash joins it.
- **Grouped sudo failures.** Failed or password-less sudo attempts are one `auth-failure:sudo` finding.
- **Paced popups:** at most one every 5 minutes (`[observer] notify_every_minutes`). New findings
  in between share it.
- **The agent sees what reeved sees.** The open findings are in every prompt, and a `findings` tool
  gives the details. It no longer says all is well while the observer reports problems.
- **A test no longer tries real sudo** on developer machines.

## New: standing orders

Work you write down once, which `reeved` carries out unattended when a finding or a schedule calls
for it. Each order has a hard scope:

- a tier cap, never T3;
- the tools that may change things;
- command globs every part of a command must match;
- path globs for file tools.

Each order also has its own budget. Anything outside the scope is refused, and the run ends as a
proposal for you. `/orders` in the TUI, or `reeve orders`. Three examples, all off, to start from.
Order files and Reeve's own config are now floor-protected against tool writes.
