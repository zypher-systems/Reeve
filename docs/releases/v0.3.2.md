Reeve asks less: reading never asks, scratch files are free, and one yes can cover a whole request.

## Update

```sh
curl -fsSL https://raw.githubusercontent.com/zypher-systems/reeve/main/install.sh | sh
```

## Changed

- **Reading never asks.** Reeve reads a command the way the shell will run it:
  - `if`, `for … do … done`, `case`, functions, and builtins like `cd`, `export`, `read`, and `[[` are
    structure, not unknown programs.
  - awk and sed programs are read. Printing and substituting run at once; an awk program that writes a
    file, pipes to a command, or calls `system()`, a sed `w`, `e`, or `-i`, and scripts Reeve can't see
    (`-f`) still ask.
  - `tool --help` and `tool --version` ask nothing, and neither do `reeve`'s own read-only commands or
    `udevadm info` and `abrt-cli list`.
- **Scratch is free.** Each session has its own folder, `~/.reeve/scratch/<session>` (`$REEVE_SCRATCH` in
  every command), and Reeve is told to keep intermediate files there. Writing there, or creating a new file
  in `/tmp`, never asks. Folders are cleared after a week.
- **One yes can cover more.** On an approval card:
  - `a` is **yes to the rest of this request**: every other change to your files runs until Reeve finishes
    answering you. (Inside a verified change, `a` is still yes to the rest of the change.)
  - `s` allows **this kind of change for the session**: writes in `~/Documents`, deletes in `~/Downloads`,
    or runs `flatpak`, not only the exact same command. The card says which.

Replayed against real receipts, 22 shell commands that asked became 6. Asking for a list of installed
packages written to a Markdown file now asks once, for the file.

## New

- **`[approvals] undoable`**, off by default. Set it to `true` in `~/.reeve/config.toml` and changes Reeve
  can undo (file writes, edits, moves, and deletes it keeps a copy of) run without asking, each with its
  undo in the chat. Shell changes, which can't be undone, still ask. The top bar shows `tiered · ↶ auto`.

## Fixed

- A verified change's checks must only read; one that writes a new file in `/tmp` or in scratch is
  refused too. (0.3.1 was never published: its tests caught this.)

## Heads up

- `a` used to mean "allow for this session"; that's `s` now. Nothing changes for root, system files,
  packages, or services: they ask every time, and the floor still needs a typed `yes`.
- Standing orders and the drafter still treat scratch and `/tmp` writes as writes.
