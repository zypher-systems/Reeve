**Fixes.** A verified change survives a stopped check, reflection waits at the spend cap, and undo
refuses when a file's permissions or kind changed since. An undone move can be redone.

## Update

```sh
reeve update
```

On 0.4.0 or earlier, run the installer once more instead:

```sh
curl -fsSL https://raw.githubusercontent.com/zypher-systems/reeve/main/install.sh | sh
```

If Reeve came from your distribution's repository, `reeve update` goes through that repository once
it carries 0.8.1; `dnf upgrade` or `apt upgrade` does the same.

## Fixed

- **A stopped check no longer loses the change.** Stopping a turn while `change_commit` was waiting,
  checking or rolling back dropped the open change: the edits stayed, and the next `change_commit`
  answered "no change is open", so neither the verdict nor the automatic rollback could happen. The
  change now stays open until its verdict is on record; the next `change_commit`, or the end of the
  next turn, finishes it. A change already undone, by a rollback that was stopped partway or by you,
  counts as rolled back rather than being tried again, and the verdict says so.
- **Reflection waits at the cap.** With the daily cap exhausted, chat refused but reflection (on a new
  session, on request, and the catch-up at start) still called the model. It now passes the same gate
  as a turn before it calls, and its spend is priced by the same rule. A session refused this way stays
  unreflected and is picked up when the cap allows.
- **Undo sees a changed mode or kind.** The undo compared only the file's content with what Reeve
  left, so a file you had locked down (`chmod 600`) after Reeve's edit was silently put back to its
  earlier permissions, and a file replaced by a link to the same text passed as unchanged. Content,
  permission bits and kind (file, link, directory) are compared now, and the refusal says which
  differs: "its mode is 0600, was 0644". Root-owned files get the same check.
- **An undone move can be redone.** Undoing a move that had overwritten a file put both files back,
  but the receipt for that undo carried an inverse that refused to run ("exists again"). The inverse
  now records what the undo put back; redoing the move checks that file is still unchanged and moves
  over it, and undoing the redo is the original undo again.

## Also

- These four came from a review of 0.8.0, along with a fifth: a receipt is written only after the
  action runs, so a command stopped or crashed midway can leave a change with no receipt. That is
  the intent-record work in design §14 and isn't in this release.
- Not exercised for this release: the live container tests for pacman and apt (no package code
  changed).
