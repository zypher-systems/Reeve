**Fixes.** What a day of driving 0.9.0 in Debian, Ubuntu, Arch and openSUSE containers turned up:
the health tile's memory figures ran into the temperature, one ledger entry was stamped in UTC, an
apt upgrade could be approved without a word about an undo that couldn't work, and a few messages
said the wrong thing. The Debian package no longer pulls snapper onto a server.

## Update

```sh
reeve update
```

On 0.4.0 or earlier, run the installer once more instead:

```sh
curl -fsSL https://raw.githubusercontent.com/zypher-systems/reeve/main/install.sh | sh
```

If Reeve came from your distribution's repository, `reeve update` goes through that repository once
it carries 0.9.1; `dnf upgrade` or `apt upgrade` does the same.

## Fixed

- **The memory figures stop short of the gutter.** On the board's health tile, `24.2G/60.4G` ran
  straight into `temp` on any machine with 10 to 99 GB of memory: the column kept 9 cells for a
  12-cell figure. The bars now give way to their figures, in both columns.
- **One clock.** A ledger entry showed `03:04` between neighbours at `22:03` and `22:05`. chrono
  re-reads `/etc/localtime` once a second and answers in UTC while that read fails. Every clock in
  the TUI (ledger, header, daily totals) now uses one offset read at startup. A DST change during a
  session is the only thing it would miss, until Reeve restarts.
- **apt says when an undo can't come from its cache.** An apt upgrade or removal is undone from the
  packages apt downloaded. Where apt.conf deletes them after every run (container images ship this as
  docker-clean) or turns `APT::Keep-Downloaded-Packages` off, the approval card now says "undo would
  have to download the old versions again", and the undo, if the mirror no longer has them, fails as
  before with nothing changed. apt(8)'s own `Binary::apt::` setting isn't counted: Reeve runs apt-get.
- **Undo of a created file says so.** It said "restored /etc/motd" after removing the file Reeve had
  created. It now says "removed /etc/motd (it didn't exist before)", and the mixed cases count both.
- **Undo refusals in their own words.** "apt can't undo this: …" and "… has changed since Reeve
  touched it" came prefixed with `io:`, which they aren't. They have their own error kind now.
- **`command -v name` is a lookup.** It was classed as running `name`, so a verified change whose
  check was `command -v cowsay` was refused as not read-only, and the shell step asked at T1. It is
  T0 now, like `which` and `type`; `command name` still runs `name` and is assessed as that.
- **Enter during a turn.** Pressing enter while Reeve was working did nothing and said nothing; the
  text waited in the box and went out glued to the next message. Now the first press says so once:
  the text stays, and esc stops the turn.
- **Smaller words.** A root file change says sudo "may ask" for a password, since with passwordless
  sudo it doesn't. `reeve doctor` tells "the unit is active, but no fresh status has reached this
  home" (a reeved on another `REEVE_HOME`, or one that just started) apart from a stopped reeved,
  and warns about a key file that isn't mode 600.

## Packaging

- **Debian: Suggests, not Recommends.** The `.deb` recommended snapper and libnotify-bin, and apt
  installs Recommends by default, so a headless Debian 13 got snapper and three timers for installing
  Reeve. Both are Suggests now. The Fedora package keeps its Recommends.
- **Arch: no debug split.** `reeve-bin`'s PKGBUILD sets `!debug` and `!strip`, so makepkg no longer
  builds a `reeve-bin-debug` package from the prebuilt binary.

## Also

- The drive (DECISIONS 2026-11-02) installed 0.9.0 four ways, the `.deb` through apt on Debian 13,
  `install.sh` on Ubuntu 24.04, the `reeve-bin` PKGBUILD through makepkg on Arch, and the RPM through
  zypper on Tumbleweed, then ran package installs, removals and upgrades, root file edits, and their
  undos. All of it worked; the list above is what read wrong around it. openSUSE stays outside the
  package tools, as `reeve doctor` says; the model used zypper through the shell, with a question per
  new command.

  changed; the apt change reads `apt-config dump` at approval time).
