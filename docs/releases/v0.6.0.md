Arch and Omarchy, and skills: jobs done your way, by name.

## Update

```sh
reeve update
```

On 0.4.0 or earlier, run the installer once more instead:

```sh
curl -fsSL https://raw.githubusercontent.com/zypher-systems/reeve/main/install.sh | sh
```

## New

- **Arch, as safe as Fedora.** Package changes can be undone. pacman has no transaction ids, so the
  receipt records what pacman logged (installed, upgraded, removed, with versions), and undo puts the old
  versions back from pacman's cache and removes what was new, in whichever order pacman accepts.
- **The AUR, on your word.** A package the repos don't have is built with paru or yay. The approval card
  shows its PKGBUILD, and names any install script it runs as root.
  - You're asked every time: YOLO and session yeses never cover an AUR build, and standing orders can't
    do one. A raw `paru -S` or `yay` typed through the shell is treated the same.
  - A system upgrade stays `pacman -Syu`. AUR updates are listed apart, with `aur:`, and rebuilt by name.
- **snap-pac.** Where it's installed, pacman already snapshots every transaction, so Reeve adds no pair of
  its own and records snap-pac's on the receipt.
- **reeved on Arch** says a reboot is pending when the running kernel's modules are gone, and reports
  security updates from `arch-audit` when it's installed.
- **Omarchy's theme.** On Omarchy, Reeve takes the current theme and follows `omarchy-theme-set` while it
  runs, light themes included. A theme of your own goes in `~/.reeve/themes/<name>.toml`, with the keys of
  Omarchy's `colors.toml`.
- **Skills.** A skill is a job you want done your way, saved by name in `~/.reeve/skills/<id>.md`: a
  one-line description and the steps.
  - Run one with `/id` (what you type after it goes along), from ⌃K, or with `⏎` on the new skills tab of
    F8 memory. Reeve also uses one when what you ask clearly matches its description, and says so.
  - Make one by saying "save that as a skill" after Reeve does something, or with `n` on the skills tab.
    The card shows the whole text, and you're asked every time.
  - Three starters are written the first time Reeve runs: `tidy-downloads`, `update-everything`, and
    `why-slow`. Delete them and they stay deleted.
  - A standing order can use a skill: "every Sunday, use the tidy-downloads skill".

## Changed

- **The default theme is `auto`:** Omarchy's on Omarchy, slate everywhere else. A theme you set stays.
- **Package search and the update list on Arch** include the AUR when paru or yay is installed.
- **A package command that fails partway** still records what it changed, so it can be undone.
- **The slash palette** lists your skills after the commands.
- **A skill edited in your editor** (`e` on the skills tab) leaves a receipt, so F4 can undo it.

## Heads up

- A skill grants nothing: each step still asks the way it always would. Writing into `~/.reeve/skills`
  any other way than "save that as a skill" or your own editor needs a typed yes.
- Undo on Arch needs the old packages in pacman's cache. If `paccache` or `pacman -Sc` removed one, undo
  names it and changes nothing.
- Undo on Arch is two pacman transactions. Where neither can go first, it's refused before anything
  changes. If it stops between the two, the failed undo's own receipt takes back the half that ran.
- The card shows an AUR package's PKGBUILD, not the install script or patches beside it.
- On Arch, pacman, its undo, and yay were tested live in a container. paru, snap-pac, and following a
  running Omarchy's theme have unit tests but haven't run on a real system yet.
- A skill named like a slash command (`update`) isn't in the slash palette; it's in ⌃K and F8.
