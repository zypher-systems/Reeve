**Features.** reeved never waits on a model call or a package query. Releases are signed, and come as
a `.deb` too. `reeve update` respects your distribution's repository. A runbook counts a success only
when the receipts show it, and shared files change under a lock.

## Update

```sh
reeve update
```

On 0.4.0 or earlier, run the installer once more instead:

```sh
curl -fsSL https://raw.githubusercontent.com/zypher-systems/reeve/main/install.sh | sh
```

From 0.8.0 on, the installer and `reeve update` install only a signed release, and every release
before this one is unsigned. So `reeve update --rollback` from 0.8.0 to 0.7.2 is refused; to go back,
use 0.7.2's own installer: `curl -fsSL https://raw.githubusercontent.com/zypher-systems/reeve/v0.7.2/install.sh | sh -s -- --version v0.7.2`.
If Reeve came from your distribution's repository, `reeve update` now goes through that repository
(below), and you can just as well run `dnf upgrade` or `apt upgrade`.

## New

- **The observer never waits on slow work.** The 6-hourly checks (package queries) and a draft (model
  calls, minutes) ran inside reeved's loop: with the drafter on, reeved was frozen most of the time,
  samples were missed, "run now" waited on the model, and the journal backed up. They now run as
  tasks beside the loop and report back when done; sampling, the heartbeat, the journal and standing
  orders keep their cadence. Each has a deadline. Checks that don't finish in 10 minutes resolve
  nothing (a finding they didn't see isn't gone; a probe that couldn't run is no verdict, where an
  empty answer used to read as "no newer kernel"). A draft stops itself between model calls after 15
  minutes, so every call it made is in the ledger; one stuck in a call that never returns is cut off
  at 35 and leaves its note on the finding, so the next pass doesn't pick it again. One of each at a
  time. `/observer` and `reeve daemon status` show what's running and since when.
- **Signed releases.** Each release's `SHA256SUMS` carries `SHA256SUMS.sig`, an ed25519 signature made
  with Reeve's release key. The public half is in the repository (`release/reeve-release.pub.pem`),
  built into every Reeve and pinned in `install.sh`; the release workflow signs and then verifies
  against that committed key before a draft exists. The installer and `reeve update` refuse a release
  that isn't signed, is signed with another key, or whose checksums changed after signing, before
  anything else is downloaded. The installer needs OpenSSL (1.1.1 or newer).
- **A `.deb`, and everything to rebuild the packages.** Each release now ships, for x86_64 and
  aarch64, a `.deb` next to the RPM and the static tarball (`sudo apt install ./reeve_<version>-1_amd64.deb`),
  a source tarball that unpacks as `reeve-<version>/`, the vendored crates, and the Fedora spec with
  both tarballs' checksums filled in, next to the AUR `PKGBUILD` as before, so a downstream builds it
  offline and pins every input. Every archive and package carries `third-party/`, the licenses of the
  crates built in. `reeve update` recognizes a `.deb` install and updates it with apt-get.
- **Updates respect your distribution's repository.** A Reeve that came from a dnf or apt repository
  (a distribution's build, signed its way) is updated through that repository, by version:
  `sudo dnf upgrade -y reeve-<version>`, `sudo apt-get install -y reeve=<the repository's version>`.
  The release's own package never replaces it; if the repository doesn't have the version yet, Reeve
  says so and nothing changes. Only a package installed by hand from the release files gets the
  release's RPM or `.deb`.
- **A runbook counts a success only with evidence.** Reflection used to take the model's "worked" at
  its word. Now a runbook's success needs the session's receipts to bear it out: a verified change
  that passed its checks, or something that ran with nothing failing. Otherwise the runbook isn't
  written, and the summary says "1 runbook left out (said to work; no receipt shows it)". "failed"
  needs no evidence; it only lowers confidence.
- **Shared files change under a lock.** `settings.toml` and the standing orders' state are read,
  changed and written while holding a lock, so two TUIs never drop each other's choices, and reeved's
  tick, a finishing run and `reeve orders run` never drop each other's claims. reeved picks and claims
  the due order in one step.

## Fixed

- A `local` connection whose host ends in the DNS root dot (`http://localhost.:11434`) no longer
  draws the "isn't this machine" warning. One trailing dot only; `localhost..` stays flagged.
- The Fedora spec named GitHub's `archive/` tarball as its source, which unpacks under the
  repository's capitalised name and whose bytes aren't promised stable, so it never built from the
  source it named. It now names the release's own source tarball.
