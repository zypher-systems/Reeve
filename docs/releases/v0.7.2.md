**Fixes.** The sudo password is asked once, not once per root step. Standing orders count every run and
every "run now". A dozen places where Reeve could act on less than it knew now stop and say so instead.

## Update

```sh
reeve update
```

On 0.4.0 or earlier, run the installer once more instead:


## Fixed

- **The sudo password, asked five to fifteen times for one request.** Reeve remembers the password
  you type for five minutes, but it treated any request that came within 15 seconds of a remembered
  answer as a wrong password and forgot it. Every root step runs in its own shell, so sudo's own
  cache never carries from one step to the next, and one action is three requests in a row: the
  snapshot before, the action, the snapshot after. The memory went every other step. Now the askpass
  helper tells Reeve which sudo process is asking: a new one gets the remembered password, and only
  the same one asking a second time means it was refused, which brings the panel back. The clock
  restarts on each use, as sudo's does. `password_minutes` under `[approvals]` sets how long (default
  5; 0 asks for every step), and the panel says so. The password still goes to sudo and nowhere
  else, and is wiped from memory when it expires or is replaced.
- **Standing orders: the daily limit stopped counting at 20.** `runs_per_day` was checked against the
  run history, which keeps 20 entries, so a limit above 20 was never enforced, and a run that started
  but never came back wasn't counted at all. Each start is now counted the moment it is claimed,
  including `reeve orders run`. State written by earlier versions still counts its day.
- **"Run now" for several orders ran only one.** The requests were all consumed and the first was
  run. They now wait until each is taken, oldest first, one every ten seconds. A request for an
  order that no longer exists is dropped. "Run now" still skips the order's frequency limits: you
  asked for now.
- **A verified change could pass on a journal that was never read.** The `journal_quiet` check
  counted the lines of `journalctl … | wc -l`, so a journalctl that failed, or ran as a user who
  can't see the system journal, gave "0 errors" and the change counted as verified. The check now
  fails, with the reason, whenever journalctl exits non-zero or warns on stderr, and counts entries
  (one JSON line each) only from a clean read.

## Made to fail closed

Each of these was found by a review of the code against what Reeve promises. None has a known field
report; all of them are the kind of thing that would have been hard to explain after the fact.

- **No action without a receipt.** Before any tool call runs, Reeve checks that it can write a
  receipt now: the lock, the chain's head, this month's file. If it can't, the call is refused with
  the reason and nothing runs. (0.7.1's outage was the mirror image: actions ran, then failed on
  their receipt.)
- **Temporary files can't be redirected.** Reeve wrote through a temp file with a guessable name
  (`.name.reeve-<pid>`), created in a way that would follow a planted symlink. It now creates the
  temp file exclusively under a random name. The root helper's check file for `visudo -cf` and
  `findmnt --verify`, which is created as root in `/tmp`, is made the same way.
- **Your state is private.** `~/.reeve` and the session directories are 0700 and the ledgers and
  transcripts 0600, whatever your umask (transcripts were 0644 under the usual umask). A spend record
  torn by a crash gets its newline before the next record, so it can't swallow it.
- **A ledger Reeve can't read in full is a floor, not zero.** A corrupt record in the month's spend
  file read as $0. The totals now show as "at least" (≥), and reeved starts no standing order and no
  draft while the file has a record it can't parse. A model call that returned neither usage nor a
  price is recorded as unknown cost instead of vanishing.
- **reeved with a config that doesn't load starts nothing.** It kept watching on default settings,
  which have no spending caps, and ran orders under them. Now it watches, pauses standing orders and
  the drafter, and says why in its status until `config.toml` loads again. A `.state.json` for the
  orders that doesn't parse stops the scheduler and is never replaced with an empty one.
- **An order run or a draft that hit an error is a failure**, whatever the model said before the
  error. The error leads the summary.
- **Reads are capped where they read.** `fs_read` loads at most 8 MiB of a file (it showed 64 KB,
  but loaded all of it) and says when there was more; search reads at most 4 MiB per file.
- **"Local" has to be true.** A connection with `kind = "local"` turns masking off and counts calls as
  free. `reeve doctor` and the TUI at start now flag one whose URL doesn't point at this machine.
- **Programs that name Reeve's own state.** `python3 -c '…open("~/.reeve/keys/x")…'` was a T1 like
  any other program. A one-liner (`python3 -c`, `perl -e`, `node -e`, …) that spells a path to
  Reeve's keys is refused; one that names its receipts or undo store, or mentions its state
  directory together with those names, needs your typed yes. The README now says what is true:
  spelled paths are refused in every mode, a program that names them needs the typed yes, and one
  that reaches them some other way is held only by the tier of running it.
- **Two verified changes begun in the same second** in two sessions could share an id; ids now carry
  four random characters.
