Standing orders by asking: tell Reeve to do something every so often, and it keeps doing it.

## Update

```sh
curl -fsSL https://raw.githubusercontent.com/zypher-systems/reeve/main/install.sh | sh
```

## New

- **Ask for an order.** Say "clear my thumbnail cache every Sunday if it's over 500 MB" or "whenever the
  disk fills up, vacuum the journal". Reeve looks first, then writes a standing order and asks you once.
  The approval card shows it in plain words: when it runs, what it does, the exact commands and files it
  may change, and the most it spends a run and a day. `⏎` approves it and it's on; reeved runs it from
  then on. Ask the same way to change, pause, or delete one.
  - Nothing answers that card for you: not YOLO, not "yes to the rest", not a session yes.
  - An order can't make another order, and neither can the drafter.
- **A form for orders.** `n` in F7 orders opens one, in five sections (what, when, what it may do, limits,
  after), with a line of help under every field and a live **What it will do** beside it.
  - Start blank or from an example; pick a schedule from choices (every day, every week, every few hours
    or minutes) instead of writing one.
  - Tick what reeved finds that should start a run, and the kinds of change it may make, in plain words.
  - `ctrl+s` saves, and points to anything missing first. `e` edits an order in the same form; `E` opens
    its file in `$EDITOR`.
- **Undo for orders.** Saving, turning an order on or off, deleting one, and editing it in `$EDITOR` each
  leave a receipt with the file as it was. `u` in F7 undoes the last change; F4 activity has them all.

## Changed

- **Saving an order changes only what you changed.** Comments, keys Reeve doesn't know, and edits made to
  the file while the form was open stay. If the same field changed in both places, the form says so, and a
  second `ctrl+s` keeps yours.
- **Limits follow the schedule.** "Every 30 minutes" gets 48 runs a day, a little under 30 minutes apart.
  Before, the default limits (4 a day, 6 hours apart) quietly slowed a frequent schedule down; the form and
  the card now say when limits would.
- **Deleting an order** can be undone, and a new order never replaces another.
- **The examples** are written the first time you open F7, once. Delete them and they stay deleted
  (`reeve orders examples` writes them again).
- **Turning an order on or off** keeps the rest of its line, comment included.

## Heads up

- Orders are run by reeved, not cron: it checks every 10 seconds. It's a systemd user service, so it runs
  while you're logged in (a locked screen counts), and a daily or weekly run missed while the machine was
  off runs when reeved next starts. Start it in `/observer`, or with `reeve daemon install`.
- An order's root commands still need a sudoers rule, since nobody's there to type a password. `s` in F7
  shows the exact lines.
- `reeve undo` of a change to an order is on the floor (a typed yes), like writing the file directly.
- Closing the form with changes keeps it until Reeve quits: `n` (or `e` on the same order) brings it back.
